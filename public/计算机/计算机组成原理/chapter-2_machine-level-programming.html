C汇编过程

汇编操作

标准寄存器

x86-64架构下设定的16个存储 64 位值的寄存器，%r开头代表64位，%e代表%r截断后的低32位 %rdi：函数中第一个参数寄存器 %rsi：函数中第二个参数寄存器 %rax：临时返回数据 %rsp：栈帧 %rip：当前正在执行指令地址，使用相对寻址时，默认%rip 为%rip的下一条指令地址 %rbx：被调用者保存寄存器

操作数

立即数：以$开头的常数 寄存器：以%开头的16个寄存器之一,使用其中的低位 1 字节 、2 字节 、4 字节或 8 字节作为操作数 内存：以（%）格式的由寄存器指定的地址空间,类似于ptr,同时 D(%rbp)代表(ptr+D),在地址上进行常数偏移,最复杂的情况下使用 D(%rbp, %rcx, S)代表*(ptr1+ S * ptr2 + D)，在引用数组时可以用来表示对基地址的偏移

数据传送指令-mov 类

mov 类指令由四条指令组成:movb、movw、movl、movq,执行相同的操作,但是数据大小分别为 1 字节 （byte）、2 字节（word）、4 字节（double word）、8 字节（quad word）

movq指令提供5种在不同操作数之间交换数据的功能，其中立即数不能作为交换目的，因为是常数没有意义，且内存与内存之间无法交换，需要通过DMA或者以内存-寄存器-内存路径完成。

leaq指令

与movq类似，但其不依赖于内存处的值，而是内存地址本身的运算与运用 movq (%rdi, %rdi, 2) , %rax：将3*%rdi的内存处的值赋给%rax leaq (%rdi, %rdi, 2), %rax: 将3*%rdi赋给%rax salq $2, %rax：将%rax左移两位，即地址扩大四倍 通过leaq和salq，将rdi的地址扩大了12倍

条件寄存器

条件寄存器仅占一位 CF：无符号整数运算时的进位标志 ZF：计算结果是否为0 SF：计算结果是否为负值 OF：有符号整数的运算溢出标志 采用setX命令完成对条件寄存器的读取，但与常见代码不同的是，无法直接读取寄存器，只能通过命令判断寄存器的值

如ZF=1，则sete tmp，tmp=1 代表最近指令产生0值。 或者用代码 tmp= (ZF == 1)，set 指令簇不发生跳转只有赋值行为

使用jX指令对条件代码进行判断并分支，j 指令簇有控制的跳转行为

选择语句

编译器首先将case语句中的最大值和最先值找出来，然后根据范围区间维护一个跳转表，存储每个条件代码块的地址，通过数组索引x来选择地址并运行该处的代码

过程

假设过程P调用过程Q，过程Q执行后返回过程P，则需要多个机制维护：

  1. 传递控制，在进入Q时，PC需要被设置为Q的代码起始地址，在返回P时，PC需要被设置为Q的下一条代码

  2. 传递数据，P必须能向Q提供一个或多个参数，Q必须能向P返回一个值

  3. 分配和释放内存，Q要为局部变量分配空间，返回时要释放空间

运行时栈

x86-64的栈向低地址生长，栈指针寄存器%rsp指向栈顶，分配空间时，指针减小。

数据传送

函数的前六个参数拥有固定对应的寄存器，如果有多余参数，将存放至栈中

栈帧

所有栈帧分布在同一块栈空间中的不同区域上，所以栈空间只有一块，只是将他划分成不同栈帧而已

调用函数创建栈帧后:

  1. 一部分参数传入寄存器，多余参数压入栈底部
  2. 压入当前调用函数的下一条指令地址也即返回地址
  1. 接下来进入栈帧真正的数据部分，主要做几件事
  • 压入%rbp：%rbp代表基地址，即上一个栈帧的底部，假如从 main 进入 foo，那么在 foo 的栈帧中压入 main 栈帧的基地址，为什么压入上一个栈帧的基地址原因很简单，在退出函数后该栈帧被舍弃，我们需要定位到上一个栈的起始位置

  • 建立当前栈帧：我们已经压入了上一个栈的基地址，那么需要更新当前栈的基地址，指向刚刚存入的%rbp 处，刚刚存入的地址起始就是栈顶的位置，所以将当前栈顶%rsp->%rbp

  • 为栈分配内存空间：将栈顶指针减去分配内存空间，保持基地址不变

  1. 退出阶段：
  • 恢复栈帧到当前栈基地址位置，当前栈帧中声明的变量直接抛弃，不用清空
  • 恢复上一个栈基地址
  • 返回

递归

数组分配与访问

对于数据类型 T 和整数 N，声明如下 :

T A[N]

这个声明有两个效果,首先,在内存中分配一个 L*N 字节的连续区域,L 为数据类型 T 的大小,其次引入标识符 A,可以通过 A 表示指向数组开头的指针 .最后数组元素 i 会被存放在地址的地方 当我们创建嵌套数组时,数组的分配和引用一般也是成立的,例如声明:

int A[5][3]

等价于创建一个 RCL 字节的连续区域:

typedef int row3_t[3];row3_t A[5]

通常来说,对于一个数组:

T D[R][C]

他的数组元素 D[i][j] 地址为:

&D[i][j]=$ x_d+L(C\times{i}+j) $

实际上对于一个 C 列的数组,使用 (C-1)L 可以代表数组的最后一个数据,而 CL 代表了下一行数组的开头,在二维数组中,将基地址加上 iCL,代表了将基地址向下偏移 i 行然后再使用一维数组的地址索引方式

struct

struct 声明一个数据类型,将不同类型的对象聚合到一个对象中,结构的所有组成部分存放在内存中一段连续的区域内,而指向结构的指针就是结构的第一个字节的地址,编译器维护相关信息记录每个字段的字节偏移.

字节间对齐: 原则为 x 字节的数据地址开头必须为 x 的整数倍,在此例中,使用 3 个字节在 c 后使得 int 数组开头地址为 4 的整数倍,使用 4 个字节在 int 数组后使得 double 数据开头为 8 的整数倍 原因:机器倾向于一次性读取 64 个字节的内存数据,如果一个数据被分配至两个数据块会导致多余处理步骤

尾部对齐: 必须保证结构体长度为最长数据块的整数倍,否则在使用结构体数组的时候仍然无法保持对齐

不同的数据声明方式会导致结构体使用不同的对齐方案,节省或浪费空间,将大块数据放在头部小块数据放在尾部

union

union 使用占用空间最大的变量的大小来分配内存,不同的类型占用一块内存,只使用其中的一个变量

内存管理

64 位地址意味着每个地址都由 8 个字节组成,总共能产生 2^64 个地址,而每个地址对应着一个字节的数据,意味着需要 2^64 个字节的内存才能将地址使用完,不过操作系统一般限制只使用其中的 47 位也即图中的 0x7FFFFFFFFFFF

Q1:地址空间使用了 47 位数,每个地址对应一个字节,假如我的内存条没有这么大空间怎么办 A1:不是每个地址都有对应的内存空间,没有分配内存的地址是没有意义的

Q2:在地址空间中连续的两个地址对应的内存上的数据位置也是连续的吗 A2:有可能不连续,内存上的空间按页管理,如果数组的相邻两位 a[n] 和 a[n+1] 被分配到了一页的尾和零一页的头,那么就会出现两个内存数据地址相邻但是位置不相邻的情况

栈位于地址空间最顶端,向下生长,通常大小为 8MB,可以在 linux 中用 limit 指令查看,如果使用栈外的地址空间寻址会发生段错误 text 部分位于地址空间最低端,存储代码 data 存储声明的全局变量 heap 用于存放通过 malloc 或相关函数申请的变量,如果每次都申请但不释放的话会发生溢出 shared-libraries 类似 text 部分,不过存储的是动态库的代码

栈溢出

使用 gets 类似函数处理输入字符时可能出现的攻击行为，通过将字符串修饰为攻击代码+填充段 +返回地址的形式，可以覆盖原本位于栈帧中的函数返回地址，在退出栈时，一般使用指令ret，意思是提取rip，通常来讲，这里一般存储的是进入函数时的下一条指令地址$rip+n，这样在退出函数时取出进入函数时存储的地址才能保证退出到正常的位置，问题在于：通过栈溢出，可以修改返回位置至栈上 ，反编译通过 section 能区分栈上数据和代码数据，但 CPU 运行时只关注当前指令 $rip，这导致如果栈上的临时数据偶然组成了一条有意义的指令的话，CPU 不会分辨这是 data 部分的数据还是 text 部分的数据，会将栈上数据辨别成代码并执行（当然通常下会将栈上数据标注为不可执行区域）。

解决方案:

  1. ASLR 随机缓冲区分配会对栈上的地址进行随机分配无意义空间导致每次进入程序时地址都不一致
  2. 使用有保护的函数 fgets
  3. 通过编译器的 canary 保护来完成预防
  4. 通过将栈上的代码属性修改为不可执行来防止注入

上面的攻击使用的是将返回地址改为栈上注入代码的地址来完成攻击，但是假如使用栈随机化，即每次栈在地址空间中是随机的怎么办呢？此时我们无法得到我们注入的代码在哪，更难的是，假如将栈空间注释为不可执行，此时即使我们凑巧猜中了注入代码的地址，让$rip 指向了栈上空间，由于其不可执行，程序会抛出 segmentation fault 段错误，导致攻击失败，所以通过注入字符来充当攻击代码就完全失效了。
