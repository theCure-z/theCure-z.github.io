Chapter 12_Virtual Memory

Aug 29, 20268 min read

地址空间

CPU 发送虚拟地址至 MMU(内存管理单元),内存管理单元将其转换至物理内存上对应的位置

  • 连续地址空间:有序非负整数地址的集合
  • 虚拟地址空间:包含个虚拟地址的集合
  • 物理地址空间:包含个物理地址的集合

虚拟内存是内存管理的一项技术,它使得程序认为自己掌控连续可用的内存,实际上的物理内存被分割为多个内存碎片,还有部分位于磁盘上,只在需要时进行数据交换,通常虚拟地址空间比物理地址空间大得多,物理地址空间取决于 DRAM 的容量,对于所有进程,虚拟地址空间是相同的

要注意的是,虚拟内存不只是“用磁盘空间来扩展物理内存”的意思——这只是扩充内存级别以使其包含硬盘驱动器而已。把内存扩展到磁盘只是使用虚拟内存技术的一个结果，它的作用也可以通过覆盖或者把处于不活动状态的程序以及它们的数据全部交换到磁盘上等方式来实现。对虚拟内存的定义是基于对地址空间的重定义的，即把地址空间定义为“连续的虚拟内存地址”，以借此“欺骗”程序，使它们以为自己正在使用一大块的“连续”地址。—Wikipedia

虚拟内存不代指磁盘或内存上的一块内存,而是一套优化内存分配的完整复杂机制

为什么需要虚拟内存?(本章三个部分)

  • 虚拟内存将磁盘上的数据缓存至 DRAM 中
  • 每个进程都使用相近的地址空间
  • 将不同进程所管理的内存空间隔绝开来

VM as a Tool for Caching

虚拟内存被组织为磁盘上 N 个连续字节大小的单元组成的数组,每个数组都有唯一的虚拟地址作为其索引(和内存中一致),将这些虚拟内存空间划分为虚拟页(大小固定的块),每个虚拟页大小为,物理内存也被分割为物理页P,大小也为P字节,虚拟页拥有以下三种类型:

  • 未创建的页
  • 创建了但是没有在内存中缓存的页
  • 缓存至内存中的页

页表

页表是虚拟内存用来判断虚拟页是否缓存在内存中的方法,如果虚拟页在内存中,需要判断在具体哪个页中,如果未命中,那么需要决定内存上的牺牲页来让虚拟页进行复制. 页表是一个页表条目(PTE)的数组,每个 PTE 由有效位和一个地址段组成,如果设置了有效位,那么地址段代表该虚拟页在内存中的位置,如果没有有效位,那么空地址表示虚拟页未分配,否则地址指向虚拟页在磁盘上的位置

页命中

虚拟地址传入,MMU 将虚拟地址转换为页表中的索引,该 PTE 有效位设置,所以虚拟页存储在内存中,通过对应物理地址查找虚拟页.

缺页

传入一个未缓存的地址(磁盘上的数据没有缓存至内存中),通过 MMU 后查找到了页表中的 PTE,该 PTE 未设置有效位,但有地址,代表分配未缓存,此时触发缺页异常,缺页异常进入内核中的缺页异常处理程序,程序选择一个牺牲页,例如 PP3 中的 VP4,假如 VP4 被修改过,将其写回磁盘,修改 VP4 对应的页表条目,再将虚拟页写入内存

当复制完毕后,返回当初导致缺页的指令,该指令会通过 MMU 再次查找页表,但是现在该页已经创建且缓存在内存中了

分配页面

假设使用malloc进行内存分配(如 VP5),现在页表中记录虚拟空间地址不缓存至内存,当内存使用时将其分配至物理内存空间中

局部性原理

当使用内存时,每次往返查找页表,交换虚拟内存与物理内存是非常低效的,这种状态叫做抖动,一个基于良好局部性的程序能合理利用当前内存中的空间,不会产生磁盘流量,通过 getrusage 能够调查缺页数量

VM as a Tool for Memory Management

实际上,内核为每个进程都提供了一个独立的页表,也就是一个独立的虚拟地址空间,这让程序员能够认为每个进程都掌控这一块相似 、连续的虚拟地址空间,代码段、数据段都分配在近似的位置(例如代码段总是从 0x400000 开始,数据段跟在代码段之后,而栈空间总是从最高位向下生长),而实际上他们对应的物理内存分散在各个角落,这样的好处是必然的,想象以下假如没有虚拟地址,如何跳转至一个函数/全局变量?它们可能存在于内存上的任何一个角落,只能使用相对于主程序的偏移来计算,没有绝对的地址了, 不同进程的虚拟地址可以指向同一个物理内存空间,比方说标准库函数,这也是动态库的原理,一次添加所有进程共享

VM as a Tool for Memory Protection

在一个 64 位的机器上,虚拟地址也不能做到 64 位,只使用其中的 48 位,而其余位可用作物理内存空间中的权限标识(例如栈上数据不可执行 /代码段不可修改)
