Integers

Unsigned （无符号）整数：∑i=0w−1​xi​⋅2i complement （补码）整数：−xw−1​⋅2w−1+∑i=0w−2​xi​⋅2i，首位为符号位，对于有符号整数而言，最大时首位为 0，最小时只有首位为 1，表达范围比无符号整型小一半。

补码与无符号整数比较会产生反逻辑的效果，例如

1.（ 补码）-1 与（无符号）0 比较，-1 的二进制表示为：11111 由于转为无符号整数所以由-1 的二进制得到的是 31，结果为（ 补码）-1>（无符号）0 2. -1的二进制为11111，而-2为11110，-1 > -2

所有情况下，在 111111 时取到 -1，在 100000 时取到最小值 Tmin，在 011111 时取到最大值 Tmax，且 Tmin=Tmax+1

可能 BUG:

  1. 当一个负数取反后可能错误，因为最大正数比最大负数的绝对值要小
  2. for(unsigned int i = n - 1; i >= 0; i--)对于这段代码而言，使用无符号整数会导致无限循环，因为当 i 运行至 0 时，i - 1= 0 0 0 + 1 1 1（补码在 全为 1 时一定为 -1）=1 1 1（无符号），得到的是 umax
  3. for(int i = n - 1;i - sizeof(char) >= 0; i--)由于 sizeof 返回 无符号整数，当两个数运算有一个为无符号整数时，结果一定为无符号，而这个无符号整数一定 ≥0，所以会无限循环

整数扩张

对于补码而言，对一个整数的位数进行扩张但不改变其大小就是将其首位复制 考虑 1100，将其扩张一位 11100，观察头两位，由于扩张，原先代表-8 的最高位变成了 8，而最高位变成了-16，两者相减，数值仍然不变 对于无符号而言，填充 0 即可

整数缩减

对于无符号而言，丢弃最高位，相当于对最高位取模 对于补码而言，不是单纯的取模，会有正负数转变的情况

面向字节的内存管理

64 位机器：通常处理的数据被分配 64 位的地址，不过只有 47 位可用，但能表示超过 10TB 的数据，远超现有内存。机器本身并不能决定是 32 位还是 64 位，是硬件和编译器的共同结果，就像可以在 64 位机器上使用 GCC 编译 32 位的 cpp 文件

小端序与大端序：假如一个变量由多个字节构成，它在地址当中的存储有两种方式，将低位数据存储在小地址中，高位数据存储在大地址中，类似于从右往左读，大端序反之。

Floating Point

二进制浮点数表示

小数点左边按照正常整数，左边按照 ∑i=−1∞​2i的形式累加如 543​=101.11

限制：表示的分数必须能被 2 的 k 次方整除，否则只能以循环小数方式实现；在相同位数下，该表示方式相较于整数范围太小

IEEE 754 表示

(−1)sM⋅2E，其中 s 代表浮点数正负，M 为范围 [1.0, 2.0)的尾数，E 以 2 的 E 次幂形式扩大小数。

由于阶码 E 被视作无符号整数，在 32 位浮点数情况下，E 的取值为 1254（0 和 255 不计入其中因为需要特殊表示），导致没有办法取到2−100 这样的小数，所以采用 E = Exp - bias 的方式，即设 Exp=1254，bias=127，E=-126~127。 对于 M，类似于科学技术法，保证 M 总是以 1.xxxx 的二进制小数表示，具体可通过二进制小数的左右移达到，如 101.010->1.0101，同时，二进制的移位可以看作二次幂运算的累计，所以可以在阶码中体现，同时对于 M=1.xxxx ，由于其形式不变，所以在编码中只记录 xxxx 部分。M=1.00…(1.0)~1.111…(2.0-ε）。

两种特殊情况：

  1. 当 E=111…111，M≠000…000，表示 NaN。当 E=111…111，M =000…000，表示 INF。

  2. 当 E=000…000，所表示的小数需要无限接近于 0，但由因为 M 代表 1.xxx＞1，所以在 E=000…000 时规定，M=0.xxx，此时 E 和 01 代表的最小值一样也是-126。

  3. 想要求浮点数等于 0 必须两件事同时成立，① 因为 E 是 2 的阶乘永远不等于 0，所以 M 必须为 0，而只有在非规格化的情况下 M=0.xxx 才有机会 M=0，所以综上必须有两个条件 M=0 且 E=0 才能得到 0
