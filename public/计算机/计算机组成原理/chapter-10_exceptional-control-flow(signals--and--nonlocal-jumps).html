Linux 进程概述

启动时创建 init 进程,其 PID 固定为 1,其可执行文件一般在/lib/systemd/systemd,所有的进程追溯到源头都可以视为 init 的子进程(孩子们我是开山老祖),Daemon 是守护进程,主要用于一些永不停止的程序比如 web 访问服务等,登录至某个服务器时,得到的界面一个登录的 shell 也是一个进程,shell 本身和其余程序没有本质区别,bash 是 linux 上最常用的 shell

Shell

bash 中,通过在命令后加入>ls &符号将命令或者说子进程移交至后台运行,此时可以继续在循环中读取命令,也就是说在后台或前台仅仅通过waitpid决定,如上章所说,僵尸进程相比孤儿进程而言更重要,这样的后台运行进程结束后父进程没有将其回收有巨大隐患 措施:当子进程结束后,内核会告知父进程子进程结束,父进程调用waitpid回收,这样的机制称为信号

Signal

信号就是一条小信息告诉进程系统中发生了某种类型的事件

  • 和异常的区别在于,异常硬性需要 CPU 通过查询异常表跳转至异常处理程序,完成了 CPU 控制流的改变,而信号只是软件上的实现
  • 由内核发送至进程,或由一个进程请求,内核接受请求后发送至另一个进程
  • 信号仅有一个 1-30 的整数来区分且其信息仅有一个整数 ID

SIGINT``SIGKILL是终止进程的信号,区别是SIGKILL无法被忽略,SIGSEGV当访问受保护的或不合法的内存区域会出现段错误,SIGALRM是一个可以发送给自己的信号,SIGCHLD是当子进程终止时发送给父进程的信号

Sending a Signal

内核通过更新上下文中的一些状态变量来发送一个信号给指定进程,内核发送信号的原因

  • 内核检测到了一些事件比如除以 0 或者子进程的结束
  • 另一个进程要求内核发送信号

Receiving a Signal

进程收到信号后可以产生如下行为:

  • 忽略信号
  • 终止进程
  • 通过用户定义的信号处理函数来捕捉(和异常的区别在于,异常的处理函数通过查异常表跳转至内核中,而信号处理是用户级别的)

信号在发送但没有被接受期间为 pending 态,同一时间同一类型只能有一个 pending 信号,多余的直接丢弃;进程能够阻塞特定的信号,能向其发送但 其不会接受 Pending/Blocked Bit:内核在进程上下文中维护关于 bit 的向量,通过设置每个向量 0/1 判断该信号是否 Pending 或 Blocked,也就是信号之间不会排队等待

Concurrent Signal

通过信号处理函数,当捕捉到信号时,跳转至信号处理函数,结束后返回原位置,信号处理程序与 main 程序处于同一个进程中,共享全局变量
