措施:当子进程结束后,内核会告知父进程子进程结束,父进程调用`waitpid`回收,这样的机制称为**信号**

# Signal

信号就是一条小信息告诉进程系统中发生了某种类型的事件

+ **和异常的区别在于,异常硬性需要 CPU 通过查询异常表跳转至异常处理程序,完成了 CPU 控制流的改变,而信号只是软件上的实现**
+ 由内核发送至进程,或由一个进程请求,内核接受请求后发送至另一个进程
+ 信号仅有一个 1-30 的整数来区分且其信息仅有一个整数 ID

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779157281030-9a70e41b-840a-4be2-aaf7-96e5a7131699.png)

`SIGINT``SIGKILL`是终止进程的信号,区别是`SIGKILL`无法被忽略,`SIGSEGV`当访问受保护的或不合法的内存区域会出现段错误,`SIGALRM`是一个可以发送给自己的信号,`SIGCHLD`是当子进程终止时发送给父进程的信号

## Sending a Signal

内核通过更新**上下文**中的一些状态变量来发送一个信号给指定进程,内核发送信号的原因

+ 内核检测到了一些事件比如除以 0 或者子进程的结束
+ 另一个进程要求内核发送信号

## Receiving a Signal

进程收到信号后可以产生如下行为:

+ 忽略信号
+ 终止进程
+ 通过用户定义的信号处理函数来捕捉(**和异常的区别在于,异常的处理函数通过查异常表跳转至内核中,而信号处理是用户级别的**)

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779172630597-a20b4779-11fb-4b02-ad6c-9ed756604258.png)

信号在发送但没有被接受期间为 pending 态,同一时间同一类型只能有一个 pending 信号,多余的直接丢弃;进程能够阻塞特定的信号,能向其发送但 其不会接受
Pending/Blocked Bit:内核在进程上下文中维护关于 bit 的向量,通过设置每个向量 0/1 判断该信号是否 Pending 或 Blocked,也就是信号之间不会排队等待

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779189469341-72f861be-30b0-409a-bef1-d5a82ca4f359.png)
