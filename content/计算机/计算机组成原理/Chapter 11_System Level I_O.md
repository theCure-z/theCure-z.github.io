# Unix I/O

在 Unix 中,文件只是一串字节的序列,与 windows 不同,unix 的文件只有几类:

+ 常规文件
+ 文件夹
+ 套接字
+ 管道
+ 符号链接
+ ...

普通文件包含任意数据,有时通过文件中是否只包含标准 ASCII 字符来判断是不是二进制文件,文本文件通过`\n 0xa(在 win 中变为 \r\n 0xd 0xa)`辨别一行的结尾
目录也是一种文件,`. ..`分别指向自身和父目录,linux 的目录是一个文件,其指向各个子目录,而子目录也是一个文件

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779192591686-3a9df1e1-8296-4832-99c6-0fa539314e6f.png)

通过 open read write close 对文件进行操作 
每个运行的进程都有三个文件描述符

+ 0 stdin
+ 1 stdout
+ 2 stderr

# 描述符表

任意一个进程都有一个单独的描述符表,描述符表中指向一个打开文件表,这个表包含所有打开的文件且被所有进程共享,文件描述符 012 拥有特殊含义而其余描述符用于那些打开后还未关闭的文件表,文件表中还有虚拟节点表,同样被所有进程共享,用来记录文件的基本信息

打开文件表存有:

+ 当前读写位置
+ 打开方式
+ 引用计数
+ 指向 v-node 的指针

虚拟节点表存有:

+ 文件权限
+ 文件大小
+ 数据块位置

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779259609247-de8ed2f7-13fb-428f-841b-614b48a1836e.png)

所以存在多种操作,比如分配多个描述符指向同一个文件的不同读写位置,此时 他们指向不同的打开文件表,因为他们的**当前读写位置不同**,但他们的指向同一个虚拟节点表

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779260021977-94d55a34-157b-4c07-9c22-2b51db9b90ec.png)

通过`fork`,子进程复制父进程的相关信息,包括描述表,此时父子指向相同的打开文件表和虚拟节点表,打开文件表中的计数器可以展示有多少个进程引用自身,在多进程打开同一个文件时,需要同时`close`才能使这个文件真正关闭

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779260175388-6f3a0a2d-a9b5-4ac4-9228-58c9f32e9276.png)

# I/O 重定向

通过`dup2`完成描述符表的复制

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779260432537-f1bd010b-04bd-44ff-809f-c2eaccd44375.png)

调用命令,如`ls`时,bash 首先`fork`一个子进程,此时`ls`继承了 bash 的描述符表,而 bash 的描述符表自然指向终端输出 tty, 所以最后结果输出至终端
而`ls > a`,本质是:

+ bash 在 parse 命令时发现存在重定向
+ `fork`子进程
+ 打开文件 a,如上文,这时 a 会分配至除 012 外的其他描述符(如 fd3)
+ 在`ls`执行之前,使用`dup2(3,1)`将 fd3 指向的打开文件表复制至 fd1 上
+ `execve(ls)`执行命令
