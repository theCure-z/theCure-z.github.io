# 并发的难题

+ 竞争:结果取决于调度策略
+ 死锁:不合理的资源分配阻碍程序进行(**如在 main 中调用 printf,此时 printf 会获取一个 lock,在这个 lock 下才能进行输出且 lock 只有一个,如果此时被信号处理程序中断并在其中调用 printf,这时信号处理程序会无限等待一个不可能分配的 lock**)
+ 饥饿:其他事件不断得到调用机会导致当前事件被堵塞(**进程 a 与进程 b 中,内核只调用 b,进程 a 出现饥饿**)
+ ...

# 开发一个并发的服务器

对于一个下图这样的迭代服务器(一个进程一次相应一个请求),当第一个用户连接后,第二个用户只能等待连接直到第一个用户退出

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779416579927-0407de2c-8253-468d-ac8a-c87ec99058d1.png)

三种开发并发服务器的方法:

+ 基于进程的
+ 基于事件的
+ 基于线程的

## 基于进程的方法

基于进程的方法,主进程专用于处理连接,每当接受到一个请求时,`fork`一个子进程专用于处理用户输入

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779416918151-98d86981-262b-49ec-a300-06e8f10dbef6.png)

## 基于事件的方法

简单来说只使用一个进程,通过检测对应文件描述符来判断哪个客户端进程发送信息来读取,而原先的方法假如有不活跃的客户端会堵塞其余客户端

## 基于线程的方法

先关注一个进程的组成:

+ 程序上下文:当前指令;栈指针;寄存器数据;条件代码;(并发切换时用于恢复的数据)
+ 内核上下文:虚拟内存表;描述符表;断点
+ 内存结构:栈;堆;全局变量;代码;动态链接库

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779428726002-11648d2d-7208-47c1-9bda-e2324d1231e1.png)

线程的组成:

+ 栈(**每个线程的栈空间都是进程虚拟地址空间中的一部分,从原进程虚拟地址空间中划分出不同份额给各个线程,线程可以访问任意其他线程的堆栈**)
+ 线程上下文(**将 PC 设置为指定函数入口**)

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779428873168-3372c5c8-9992-45c4-b3ea-07e9fa9ccb1e.png)

多线程的模型:不同栈+线程上下文组合成不同线程,而其余部分保持不变,不同线程享受相同的动态库/代码/堆数据/内核上下文,但拥有独立的栈空间,也就是私有的局部变量,它们同属于一个进程所以 PID 相同,但拥有各自的线程 id TID
多线程的优点:每个线程拥有自己独立的 PC 和 SP,在切换线程时,没有那么多数据需要保存,只需要切换关于线程上下文的部分,而对于虚拟内存/页表/描述符等一致

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779428936971-2d7aa4f3-9b92-422e-a949-19833790eaa6.png)

与进程树结构不一样,线程一般以池的结构表示,他们只是访问相同代码和数据的并发流池,内核负责调度各个线程让每个线程获得时间

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779430691371-3f830e87-358e-4160-85e9-604250f202ad.png)

和进程的并发概念类似,不同线程之间声明周期重叠也会产生线程的并发

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779430791658-ea4f4ff3-e1a8-4d9f-b8d7-b5d3b8dc16ef.png)

对于多核处理器而言,能完成真正的并行处理多个线程

## 接口

![](https://cdn.nlark.com/yuque/0/2026/png/58377233/1779433089687-b0cf2c97-758d-40d5-b64b-1779c171cc87.png)

`join`和`detach`是两种线程生命周期管理的不同策略
+ `join`让主线程阻塞式等待子线程结束,并回收资源(**join 看起来没有用处,例子:仿真过程中,不同线程负责各个独立区域的仿真,但主线程需要等待各个线程结束后才能继续进行**)
+ `detach`分离子线程,让系统自动回收资源
